Rule zero · supply chain

The seven points

1 · UX-DR3: theme, edge-to-edge, predictive back, own icons

5/5no new story
Winston opened with a dedicated foundation story. The other four said no: it delivers no user value.
  • Story 2.1 gets the foundation: Theme.DeviceDefault*, no AndroidX/Material/Compose on the runtime classpath, insets, enableOnBackInvokedCallback, own vector icons.
  • Stories 3.4 and 3.5 only verify inheritance. Story 5.1 gates the icon set (about 30, no bitmaps).

2 · UX-DR12: custom views not named

5/5gap was wider
The room found that TxIndicatorView was missing too, not only the two reported views.
  • TxIndicatorView is created in 2.3, IrKeyView in 3.5, RemoteCardView and FabView in 3.4. Each class is born in the first story that uses it.
  • The announced error text never contains a blaster host or IP.

3 · UX-DR14: left-handed mode, haptics, 130% font scale

5/5kept in v1
Not in the PRD, only one line of the UX spec. Sally wanted audit-only; the cost of one switch won the room.
  • Switch in Story 3.8; FAB and rockers mirror in 3.4 and 3.5; D-pad stays centered.
  • VIRTUAL_KEY once per press, not on every repeat. Icons next to labels above 130%.

4 · AR11: manifest permissions

5/5no new story
Vex's rule: no dormant permission that a future dependency could exploit.
  • Each permission is declared by the first story that uses it: TRANSMIT_IR in 2.3, INTERNET in 4.3, ACCESS_LOCAL_NETWORK in 6.5.
  • Story 1.2 adds a CI check of the merged manifest against an allowlist. Story 5.6 ties the release manifest and Data safety to it.

5 · AR10: network executor, timeouts, cancellation

5/57 ACs in Story 4.3
Three people used the same proposal id for three different texts. The host renamed them and asked for one merge.
  • netExecutor (2 threads, bounded queue) created in app and injected; 5 s connect and read, not a total cap.
  • At most 3 https redirects on the allowlist; size cap; signature and SHA-256 before parsing; cancel deletes the partial file; nothing sensitive in logs; progress in MB with Cancel.

6 · UX-DR15: the "Code details" view

5/5new Story 3.9
Winston, John and Vex first leaned toward an AC in an existing story. Amelia and Sally argued it is a new screen (key list plus dialog), and John came round on one condition: keep it small. A story it was, deferrable if the budget tightens.
  • Read-only, opened from the S5 overflow. A fixed allowlist of fields, plain text only, "Copy code" on explicit action.
  • The only place for technical terms, with a declared exception for the maker flows 2.2 and 3.3.

7 · UX-DR7: Add screen entries only in the empty state

5/53 ACs in Story 4.4
  • "Import from file" and "Enter code manually" are always visible in S3, in every state including loading and offline.
  • They open the existing 3.3 and 2.2 flows; the import keeps the same picker, parser and limits. No second validation path, no permission.

How the room worked

  • Five agents messaged each other directly; every message also reached the host. Qualified majority was 4 of 5, with a cap of 20 turns each. Nobody came close.
  • Real friction was about scope and value, never about the facts: every claim was checked against the spec, the PRD or epics.md.
  • Proposal ids collided three times (P5.2, P6.2, P6.3). The fix was renaming and asking for one merged text before any vote counted.
